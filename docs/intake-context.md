# 连续文本录入与候选依据

Quick intake 接受按项目分段的连续文本，先生成可编辑候选，确认后才写入。该流程始终是 **规则辅助，未连接 AI**；没有模型网络请求。真实 Qwen 流程仍是独立、默认关闭并需明确外发确认的适配器，不能用本评测宣称真实模型质量。

```text
Atlas:
- Prepare a synthetic brief
- Coordinate Meridian

Project: Synthetic Orchard
Owner: Synthetic reviewer
- Draft a checklist
```

第一条事项可按 Atlas 别名匹配；第二条同时有标题 Atlas 和事项中的 Meridian，默认保留在 Intake inbox，显示两个候选及各自依据。选择目标后还需勾选该行的歧义确认，再进行整批确认。服务端重新解析文本中的候选，对缺少二次确认的多项目归属拒绝整批创建。可以继续保留在 Inbox，之后再分配。

## 支持的规则

| 输入 | 候选行为 |
| --- | --- |
| `Project: …` / `项目：…`，`Atlas:`，Markdown `## …` 或 `[…]` / `【…】` 标题 | 后续条目继承该项目上下文，直到下一标题；空行不自动结束分段 |
| `-`、`*`、`•` 或数字列表 | 去除列表标记，保留事项内容及原文 |
| 标题后、第一条任务前的客户/负责人/阶段/备注标签 | 补充此段的候选资料；互相冲突的信息留空并提示 |
| 明确标签、同一行多个 `Task:` / `任务：` | 分成独立可审阅事项，保留同一原文行和分段编号 |
| 完整名称、别名、部分名称、正文提及 | 显示匹配依据；部分名称和多候选不自动选定业务项目 |
| 英文短词、网址/邮箱 | 英文别名按词边界匹配，单字符别名仅接受明确标签；网址和邮箱中的词不作为正文项目提及 |
| 不认识的人、阶段、相对/无效日期 | 不补造事实；保持未分配、待补阶段或空日期，保留来源供审阅 |
| 任务内容中的逗号、分号续句 | 保留文本，不把普通标点后的内容静默丢掉 |

这是可解释的格式/名称规则，不是任意自然语言理解。无标题的复杂叙述、代词指代、跨段隐含关系和含混时间可能仍需人工编辑或暂存 Inbox；没有承诺自动解析所有会议纪要。超长任务标题明确提示缩短，完整原文仍保留。最多 200 个候选、1,000 个文本源行，每段最多 20 个来源上下文行，超限报错而不是部分保存。

## 保存、来源和撤销

审阅页展示原文行、项目标题/元数据上下文行和候选项目依据。可改目标、编辑或排除事项；已有项目资料不因录入被覆盖。同名新项目只补缺失字段，互相矛盾的已知字段继续拒绝整批保存。缺失资料可先存草稿，任务工作周默认空，截止日不等于本周安排。

收据保留源文件/原文、行号、分段和上下文；审计同时包含标题行与事项行。暂存草稿恢复这些依据和编辑，但重置歧义、重复及整批确认，须重新审阅。数据版本冲突、幂等提交、原子创建、后续改动保护和撤销边界沿用既有实现。新字段都是可选 JSON 扩展，无新数据库迁移；旧收据与旧暂存草稿仍可读取。
