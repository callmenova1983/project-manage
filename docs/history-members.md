# 完整周历史与稳定成员关联

本批在 `f2b128b` 上增量实现，继续使用深色紧凑列表。没有部署、合并或改动真实客户数据库。

## 周统计与分页

此前周变化使用最近 500 条快照记录，较早的本周记录和筛选项目可能被遗漏。现在首页周变化和 Activity 使用完整范围查询，统计覆盖该范围的全部数据库记录，明细分页返回：首页每页 7 条、Activity 每页 25 条，API 单页上限 100 条。

- 周从 **UTC 周一 00:00（含）至下周一 00:00（不含）**。日期选择归一到所在周的周一；清除 Activity 日期查询全部日期。时间显示、每日分布、筛选和统计统一为 UTC；未增加可配置工作区时区。
- 首页排除初始化示例；History 链接保留所选周、项目筛选范围和排除示例选项。无项目筛选时包含已移除项目及工作区级历史；显式空项目范围返回零条，不退回全部项目。
- 搜索匹配保存的操作者、动作、来源和变更后内容。服务端和本地演示共用过滤/统计逻辑；界面语言不改写原文搜索内容。
- 完成数统计保存的状态转换，排除创建、导入、恢复和重复版本转换；不是当前已完成任务数或进度百分比。
- 第一页固定时间截止点和记录水位；后续页按时间与 ID 稳定排序，新增的回填日期记录不会混入。筛选变化重置页码；已加载多页时，新工作区变更提示刷新，保留正在查看的列表。
- 加载/失败不会显示伪零。旧事件链接使用独立鉴权查询；若不在当前页，会单独显示并明确不计入当前筛选总数。

`POST /api/activity/query` 是只读查询，复杂筛选放在结构化请求体，沿用登录、来源和 CSRF 检查，不写审计或业务数据。`GET /api/activities/:id` 按当前工作区鉴权。快照、兼容的 `GET /api/activities`、项目详情的近期预览及 JSON 导出仍保留最近 500 条；完整查阅走新查询，完整备份使用 SQLite 工具。

查询利用工作区/时间索引选择范围，逐条聚合，响应只保留当前明细页。已用 1,375 条跨年合成历史验证范围与分页；未据此宣称百万级历史、负载或长期运行验收通过。

## 成员字段和兼容性

- 项目 `ownerId` 单选负责人、`participantIds` 多选参与者；任务/子任务 `assigneeId` 单选执行人。引用现有工作区账号的稳定 ID，独立于姓名。
- 旧 `owner` / `assignee` 文本继续有效，不猜测账号；即使姓名完全匹配，也需明确选择。重名选项展示邮箱区分，可保留文本或改为未分配。
- 当前显示和任务搜索解析最新姓名；历史原始姓名不追改。新审计保存 `actorId`，旧审计不补造身份。
- 停用/待激活成员的原有关联可保留，新关联只接受启用成员。其他工作区或不存在的 ID、重复参与者被拒绝，导入失败整体回滚。
- 旧客户端省略 ID 且姓名未变时保留原关联；明确 `null` 清除单选 ID，`[]` 清除参与者。旧客户端改成不同文本则回到文本关联。
- 相同工作区导入保留有效关联；跨工作区导入不按姓名匹配，需要先明确清除或映射 ID。历史恢复也校验成员，不能借恢复重新分配已停用账号。
- 成员目录只给同工作区登录用户返回 `id/name/email/status`，不包含密码、会话、角色或模型配置。字段只描述协作关系，**不改变项目查看/编辑权限**。

本地演示使用同样规则，所有内容留在当前浏览器，不请求正式 API，不能替代共享后端。

## 升级、备份与回退

迁移 `006_activity_range.sql` 只新增 `activities(workspace_id, julianday(created_at), id)` 索引，不重写账号、项目、任务或历史。成员字段是 JSON 可选扩展，不自动迁移旧姓名。

先按[一致性备份说明](runtime-entry-recovery.md)在批准的私有目录生成快照。启动新版本在事务中应用 006；大数据库建索引耗时需在隔离副本评估，不以开发样本估算生产维护窗口。

自动化验证：合成 v5 → WAL 一致性备份 → v6 升级 → 业务快照相等 → 移除索引/迁移记录 → 重新应用 → 检查独立 v5 备份。既有 v3 升级/恢复测试也继续执行，只使用临时数据库。

在隔离副本验证索引回退，可在事务中删除 `activity_workspace_instant` 和迁移记录 6；这不回滚成员字段或期间业务修改。旧程序不保证保留新 JSON 关联字段，正式代码回退须先停止写入、核验备份与兼容性、明确期间新增数据处理，再另行批准切换。不要覆盖运行中的数据库；本批未进行真实恢复切换。
