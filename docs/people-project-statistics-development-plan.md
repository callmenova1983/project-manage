# 人员与项目统计：表格交互与开发计划

日期：2026-10-17。状态：功能开发与功能验收完成；性能测试按用户2026-10-18要求暂缓。适用范围为用户选定的[负责人汇总与项目明细联动方案](design/people-project-statistics-2026-10-17/refinement-plan.md)。本计划替代早期团队工作台扩展计划中与本模块相关的开发安排，不包含日报、任务生成、排班、身份迁移或绩效评价。

## 1. 交付目标

打开即可看到需要关注的负责人及项目；两步内定位明细；常用筛选与排序不必重复设置。页面只读分析，复用现有项目/任务详情入口，不另建业务编辑流程。

页面保留两个统计视角：“项目负责人”“任务负责人”。前者统计其负责项目内的任务，后者统计直接分派到该责任组的任务。两者分别记忆设置，不按同名自动连接账号或通讯录。

## 2. 筛选如何做到方便

| 功能 | 交互约定 | 首版范围 |
| --- | --- | --- |
| 搜索负责人 | 支持中文、完整拼音、首字母；输入后约200ms生效，Enter立即生效，中文输入法组词结束后再检索 | 两种视角均支持；纯文字姓名同样可搜，不因此认领身份 |
| 搜索并选择项目 | 独立的可搜索多选项目框，支持清空；不与负责人搜索混用 | 选中项目只统计这些项目，避免用户不知道搜索改变了什么 |
| 项目阶段 | 多选，含“阶段待补”；选中后立即生效 | 同一条件内为“或”，负责人/项目/阶段不同条件之间为“且” |
| 关注条件 | 单选快捷项：全部、有待协调、有明确逾期 | 这是筛选责任组，不是把该组其他任务删掉；保留全貌 |
| 未填写责任人 | “只看未填写”独立开关 | 项目视角为项目负责人未填写；任务视角为任务责任人未分配 |
| 当前条件条 | 表格上方显示条件标签、结果行数；标签可逐个删除 | 条件改变立即更新汇总与明细；“清除筛选”保留排序及列设置 |
| 空结果 | 显示导致空结果的条件，并提供清除筛选 | 不回退到全部数据，不把失败当零结果 |

常用工具栏只放负责人搜索、项目选择、阶段和排序；关注快捷项放下一行，更多显示设置收入菜单。多选下拉内部提供搜索与清空，不在每次选中后关闭。负责人搜索不混入任务标题；未来如有任务全文检索需求，再作为独立条件增加。

部门暂保留为组织背景，不作为默认业务筛选：当前多数负责人只有文字，不能通过同名把项目自动归属部门。工号检索仅适用于明确关联的人员，不在文字责任组中猜测工号。

首版不加入含义模糊的“本周完成”等时间筛选。若后续加入日期，必须明确按工作安排、截止日期还是活动发生时间统计；当前已完成任务数不等于期间完成量。

## 3. 自动排序与表头排序

默认“关注优先”，规则公开、确定且不依赖AI评分：**明确逾期数降序 → 待协调数降序 → 未完成数降序 → 项目数降序 → 姓名升序 → 稳定分组键**。不把这种顺序称为人员忙闲或绩效排名。

| 排序入口 | 行为 |
| --- | --- |
| 排序下拉 | 提供关注优先、项目最多、未完成最多、待协调最多、明确逾期最多、姓名顺序 |
| 数值表头 | 第一次点击降序，第二次升序，第三次回到当前预设；箭头和文字说明当前排序 |
| 姓名表头 | 第一次升序，再降序，再回到预设；中文使用一致的拼音排序规则 |
| 主排序相同 | 使用同一“关注优先”次级比较器，去掉重复主字段，最后以姓名及稳定键保证结果不抖动 |
| 缺失值 | 始终放末尾；未知不当作0。实际计算出的0仍参与正常数值排序 |
| 未填写责任人 | 默认固定在正常姓名组之后，视觉分隔、明确说明；“只看未填写”时正常展示 |
| 总计行 | 固定在表尾，不参与排序；统计全部筛选结果，不是当前一页 |

排序作用于整个结果集，之后才分页；禁止只排序当前页。排序只改变统计页面的显示，不写回项目或任务的业务顺序。首版不做多列拖拽排序、手写公式或复杂排序编辑器。

自动排序指数据、筛选变化后自动重新计算当前规则，不能覆盖用户已经选择的表头排序。筛选变化保持排序；切换统计视角恢复该视角自己的上次排序。

### 刷新时避免表格跳动

复用现有后台同步机制。没有交互时，一次性应用新快照、重算汇总与顺序；选中项按稳定键保留，不能按旧行号选中别人。

用户正在表格内点击、选择文字、操作菜单或键盘焦点停留在表格控件时，暂缓应用整个新快照，显示“有新数据 · 更新”。离开交互区域且无待完成操作后自动应用，或由用户点击更新。不能只更新数字却保留旧筛选集合，导致汇总和明细不一致。仅“选中一行”本身不锁住刷新。

手动改变筛选或排序应立即执行，不被交互保护阻塞。新快照中选中项消失时清空明细并说明原因，不静默切换到另一人。刷新失败保留上次成功数据，明确数据时间和重试入口。

## 4. 汇总、筛选和明细的一致性

统一计算顺序：权限内快照 → 全图识别有效末级任务 → 项目/阶段范围 → 按当前责任视角分组 → 负责人搜索及关注条件 → 总计 → 全量排序 → 分页。

- 项目负责人视角按明确账号引用分组；仅文字的按文字单独分组。没有任务的项目仍计入项目数，并显示“暂无任务记录”。
- 任务负责人视角先限定项目范围，再按任务责任分组；项目数为这些任务涉及的不同项目数，不沿用项目负责人视角的数量。
- “有待协调”保留待协调数大于0的责任组，但该组的总数、未完成、已完成仍覆盖其当前范围内的全部项目/任务。条件标签明确写“仅显示有待协调的责任组”。
- 顶部摘要与总计使用全部筛选后的责任组，未填写组默认计入；17名员工/5个部门等组织背景单独标注，不随任务条件伪装变化。
- 点击姓名/项目数：右侧展示该组当前筛选范围的全部项目；项目详情再进入共享任务入口。
- 点击未完成、待协调或逾期数：右侧切换为相应任务明细，并显示“某责任组 / 待协调 / N项”及返回项目明细入口；明细集合必须准确等于被点击数字对应的任务ID集合。
- 右侧明细可独立按阶段、任务数、未完成、待协调或明确逾期排序；这种排序不改变左侧范围或总计。
- 切换左侧责任组时清除右侧旧状态下钻，恢复该组项目明细；数据刷新保留仍有效的当前下钻。
- 明确逾期只依据工作区今天和已填截止日期；待协调与逾期为未完成子集；不能累加成总任务数。
- 所有关系均为现有事实，不按编辑参与记录推断执行人员，也不把项目内全部任务归为项目负责人本人执行。

## 5. 常用设置、返回恢复与展示

| 项目 | 设计 |
| --- | --- |
| 自动记忆 | 每个视角分别记住筛选、排序、每页数量、列显隐、舒适/紧凑行距；只存查询设置，不复制业务数据 |
| 返回恢复 | 从项目/任务详情返回，恢复原筛选、选中组、页码和滚动位置；目标已删除或不再匹配时说明原因 |
| 常用视图 | 支持“保存当前视图”、命名、覆盖自己的视图和删除；最多10个，包含明确的范围与排序 |
| 设置隔离 | 按工作区、当前账号、服务端/本地演示模式隔离，本浏览器保存；不承诺跨设备同步 |
| 状态优先级 | 显式URL参数优先于个人记忆，再使用默认值；分享链接序列化完整查询状态，不借用接收者个人默认条件 |
| 无效参数 | 项目已删除、未知阶段或责任组等范围参数显示错误/空结果并供清除，不自动放宽到全部；展示参数错误可说明并回退默认 |
| 两类重置 | “清除筛选”只清条件；“恢复默认”重置该视角筛选、排序和展示设置；常用视图保留 |
| 固定表头与列 | 主表固定表头、负责人列；数值右对齐，行悬停、选中行和键盘焦点清楚 |
| 列设置 | 负责人及核心范围列必须保留，其他数值列可隐藏；隐藏列仍可参与已有排序并在排序入口标明 |
| 分页 | 主表默认25行，可选50/100；项目/任务明细单独分页；条件或排序变化回第一页，显示总行数 |
| 小屏 | 优先呈现负责人、项目数、未完成、待协调；明细在抽屉中查看，数值仍可访问；桌面保持左右联动 |

搜索输入使用URL替换而非每个字符新增历史；明确视角/预设切换可进入浏览器历史。搜索框的输入草稿不写入业务库。存储不可用时仍能使用页面，只提示设置无法记住；损坏或较新版本的已存设置不被静默覆盖。

估算按1名熟悉项目的全栈开发、产品反馈及时、复用现有组件，合计 **7–11人日，约2–3个工作周**。这是估算，业务数据自动变化、浏览器问题及额外需求需重估；不套用早期16–24人日的扩展计划。

| 批次 | 工作项 | 工作量 | 可交付结果 |
| --- | --- | ---: | --- |
| A：统计与查询基础 | ST01 两视角聚合及准确明细ID集合；ST02 筛选schema和组合规则；ST03 预设/表头排序比较器 | 1–2人日 | 口径、筛选和全量稳定排序可独立验证 |

| C：持续使用便利性 | ST07 偏好记忆、常用视图与返回恢复；ST08 分页/列设置/密度和刷新稳定性 | 1–2人日 | 不必反复设置，刷新时不会错误选人或突然跳行 |

## 8. 验收用例与完成标准

1. **组合筛选可解释。** 人员搜索＋多个项目＋多个阶段＋关注条件结果正确；同条件或、跨条件且；每个标签可单独删除；清除筛选不改排序。
2. **关注条件不吞数据。** 固定样本中某组13项目、41任务、29未完成、3待协调，筛选“有待协调”仍显示41/29/3；点击3仅下钻到这3个任务。先限定项目/阶段后，所有数字按新范围重算。
3. **排序准确。** 9/41/106等按数值排序；相同值、同名不同稳定ID、空值、未填写组、总计行均有明确行为；排序先于分页；切换条件不意外重置排序。
4. **两视角不串统计。** 项目负责人和任务负责人分别计算；文本同名不自动合并到账号；只有项目没有任务显示“暂无任务记录”，不显示“已完成100%”。
5. **联动能对账。** 顶部/全量总计/分页/下钻的范围一致；部分明细标出已展示数和总数；筛掉当前行后不继续显示旧人的明细。
6. **设置可恢复。** 返回、刷新、关闭重开后恢复适用设置；换账号/工作区/模式隔离；URL覆盖记忆；常用视图失效条件不会扩大访问范围。
7. **刷新不打断操作。** 模拟20秒快照到达、行排序变化、选中项删除、网络失败及恢复；操作中提示更新、交互结束应用一致快照；按稳定键保留选中和焦点。
8. **可访问。** 表头按钮可键盘操作并有 `aria-sort`；结果数变化有适度提示；不能只靠颜色表示风险；375/768/1536px布局与长中文名称可用。
9. **性能单独测（2026-10-18 按用户要求暂缓，不作为本次交付前置条件）。** 当前实际规模及隔离合成200项目/5000任务上验证查询结果和全量排序。筛选/排序浏览器响应目标p95≤200ms（从实际查询提交至正确结果完成绘制，不把输入防抖藏入指标；同时报告含防抖端到端时长），初次可用目标p95≤3秒；记录环境及原始样本，不能以Node计算时间替代浏览器测量。

历史[筛选性能记录](filter-performance.md)中的280.4/363.1ms尚未达到200ms；本表采用分页并不允许少算隐藏数据。若本次仍不达标，记录实际结果并调整索引/渲染策略，不宣称已经达标。真实手机/慢网与桌面模拟结果分别记录。

验证执行：领域与查询单元用例 → 本地演示及HTTP快照一致性 → 浏览器主流程 →类型检查/构建及必要回归。纯统计页不得触发任务、项目或人员写入。
