### 新旧链路对照记录格式

使用 Node 24 执行 `./node_modules/.bin/tsx scripts/compare-assistant-runs.ts baseline.json candidate.json`。退出码 0 表示所提供记录满足门槛，1 表示失败，2 表示证据不足或输入非法。该工具不能认证输入记录的真实性；必须同时保留实际调用日志、模型配置及逐条人工判定依据。使用相同模型参数、环境和语料，交替运行新旧链路，包含失败请求耗时，不得只选择成功或最快的样本。合成回归集不代替独立准确率验收集。

每份 JSON 包含 `model`、`corpusHash`（原始语料 SHA-256）、`inputKind`（text/ocr/voice）、`actualModel`、`samples`。每条 sample 包含唯一 `id`、`durationMs`、`inputTokens`、`outputTokens`、`passed`、`criticalErrors`。缺失用量填 null，不能填 0；每次观测 ID 应包含样例和重复轮次。`passed` 和关键错误数量需要根据业务验收核对，不由 HTTP 成功推断。OCR、语音单独记录，目前未约定其性能门槛，因此工具不会将其判为全部通过。至少 20 个观测仅是计算门槛，不代表统计置信度充分。

## 当前实现

- `AssistantDock.vue` 在路由外常驻，桌面可拖动宽度、展开和收起，手机使用可视视口高度。顶部全局入口和旧录入链接汇入同一个助手。

- 查询从真实快照读取，不生成业务写入或模型调用。当前支持项目进展及今天、本周、全部时间的任务筛选；不是任意问题的通用推理查询。
- 每用户、每工作区保存会话，版本冲突要求明确恢复；本地备份用于断网恢复。恢复界面不会自动重放写入。演示模式也保存待处理 proposal 及其最终状态。
- 资料按单文件用途分流：报价/方案等归档，记录/会议截图用于识别。未能判断时才询问。手动归属、类别和关联任务保存在草稿内。
- 语音默认 `qwen3-asr-flash`，复用现有 Qwen 服务端凭据、区域、额度；文本模型不变。浏览器录音转换为 16kHz 单声道 PCM16 WAV，单次最长两分钟；识别后填入可编辑文字，不自动提交业务操作。录音不作为原附件存档。
- ASR 请求先校验录音再预留额度，同一 requestId 不会再次调用提供方。实际用量记录提供方返回的 tokens/seconds；缺失时保留未知。
