# 八周完善计划

本计划在本次完整开发、必需缺陷修复和本地验证之后执行。不是定时任务，不代表已经部署或承诺自动上线。目标始终是让全员快速了解已发生的事实、已完成事项、今天／本周具体工作及需协调事项；进度比例只作辅助，不增加角色权限孤岛。

估算条件：1 名前端、1 名后端与兼职产品／测试可投入；每周结束演示可运行版本并核对验收证据。若人员、真实数据量或基础设施不同，先调整容量，不压缩质量门槛。

## 紧接着细化的实施项

1. **首页密度与可读性**：维持 40–48px 桌面收起行；项目名 16px、事实正文 14px；长汇报在详情完整可读，移动端不截掉任务名。按宽度验证 390／768／1024／1536，不用一个断点隐藏关键事实。
2. **交互一致性**：所有行内编辑提供相同保存、取消、冲突恢复语义；子任务父级切换必须重建草稿；跨周时明确保留／清空哪些日期；筛选与范围纳入 URL 状态。
3. **来源和审计**：原文保持 exact source，解析只使用副本；同项目多条建议在应用前展示合并内容；普通属性修改不更新汇报人／时间；日期修改保留相邻原文和版本。
4. **工程维护**：拆分积累的页面样式和 API 路由，组件只负责交互；保持 HTTP／local 适配器相同契约；用契约测试覆盖两种模式，减少行为漂移。
5. **验收记录**：每次修改附对应回归、桌面／窄屏截图、已知限制；自动化检查与人工视觉验收分别记录，不把构建成功当作上线批准。

## 每周结束的决策

保留完成证据、实际用户反馈与遗留风险；按 P0→P1→P2 顺序调整下一周。真实 AI、自定义字段和更多视图可延后，事实准确性、共享编辑、数据恢复与主路径可用性不可用新功能替代。
