# 架构初稿

## 当前边界

文档和类型草稿阶段，以下模块均待实现。公开仓库只收录通用规格、代码和合成测试数据。生产业务资料不进入源码仓库。

## 模块

建议 Vue 3 + TypeScript Web、Node.js + TypeScript API、MongoDB 持久化。具体依赖与部署方式未确定。Web 通过 API 访问业务逻辑；API 负责身份、公司成员权限、运行时校验、版本检查、审计和模型适配。

## 权限与协作

公司内所有成员可以读写全部项目。负责人字段仅表示工作责任，不参与项目访问隔离。API 在公司/工作区边界隔离数据，防止匿名访客或其他公司访问。不能用自定义字段绕过身份检查。

编辑使用乐观并发版本控制；检测到版本变化时展示差异和冲突。记录操作者、时间、来源及变更，可恢复历史版本。实时更新可通过服务端事件或 WebSocket 实现，具体方案待验证，断线重连须补取缺失版本。

## 数据模型（规划）

- Workspace / Membership：公司范围和成员身份
- Project：名称、别名、公共核心字段、生命周期阶段、责任维度、负责人、自定义配置与版本号
- LifecycleStage：五阶段配置；与销售/实施运维/研发等责任维度独立
- ProjectContent：任务、里程碑、资料、会议的共享归属、标识、时间和版本；具体对象保留各自结构
- SourceDocument / SourceVersion：输入原文、版本、录入来源和时间
- ExtractedItem：来源片段、进展/待办/负责人/日期/部门候选值、匹配项目及不确定项
- AiProposal：建议、依据、审核状态、确认人及应用结果
- AuditEvent / ContentVersion：变更历史、操作者和恢复依据
- AgentReviewRun / RiskFinding：每日检查范围、数据水位、状态、证据、风险与解决情况

当前 packages/domain/types.ts 只是最早的项目/任务类型草稿，未覆盖本页完整模型，实施前需同步修订。

## 原地编辑

卡片保持在看板布局中，双击进入局部编辑状态。粘贴入口支持文字和表格解析；解析与 AI 建议在当前位置展示。常规编辑不使用弹窗或单独表单页面。保存中、失败、冲突与撤销状态需清晰可见；键盘操作和误触恢复应一起测试。

## 多项目材料处理

1. 保存输入原文及不可变版本，生成可追溯片段引用。
2. 拆分项目相关片段和条目，提取结构化候选字段。
3. 基于项目名称、别名及上下文生成匹配候选和依据；近似匹配不等于已确认归属。
4. 就地展示建议，对不确定归属、合并和覆盖冲突逐项请求确认。
5. 经正常业务 API 应用确认后的变更，记录输入版本、提取结果、审核人和审计事件；不静默删除或合并。

## 核心 Agent 与分析（规划）

针对通常 100 个以内项目，优先建立可观察的增量审视流程，再以真实规模基准测试确定容量。确定性查询负责统计与规则信号，模型负责证据解释和风险建议。每次检查记录数据水位、覆盖范围、失败项、模型用量与重试状态；重复发现须去重，不把部分检查成功报告为全量完成。

每日调度尚未创建或启用。时间、时区、接收人、通知策略、数据处理方式和成本上限需明确配置。

## 安全与 AI 边界

模型只从服务端调用，密钥不进入客户端或仓库。按需求传递最少上下文；输入文档及模型输出均为不可信数据，不得执行任意指令或绕过业务权限。输出经过结构校验，并保留来源证据。模型失败或费用限制不应使基础项目管理不可用。

日志脱敏，富文本和链接防注入。测试应覆盖公司隔离、全员共享编辑、并发冲突、版本恢复、材料拆分与不确定匹配；仅使用虚构或脱敏数据。
