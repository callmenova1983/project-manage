# 项目结束、归档与维修

项目状态独立于阶段。例如“运营维护”项目可以处于“已结束”，有维修工作时再重新激活，原阶段保持不变。

## 状态与操作

| 状态   | 日常工作                                   | 编辑与查阅                       | 适用情形                 |
| ------ | ------------------------------------------ | -------------------------------- | ------------------------ |
| 进行中 | 默认显示，参与工作安排与待办提醒           | 正常编辑                         | 正在交付或维修           |
| 已结束 | 默认隐藏，不再参与默认工作台及任务风险提醒 | 保留编辑和查阅能力，可重新激活   | 已交付，偶尔需要维护     |
| 已归档 | 默认隐藏，不再参与默认工作台及任务风险提醒 | 只读；可查任务、进展、资料和历史 | 长期不动、需要保留的项目 |

操作入口：项目列表名称旁的归档图标（桌面移入项目行时显示），或项目详情的“更多项目操作 → 管理项目状态”。已结束、已归档的详情顶部也提供状态管理入口。

项目列表的“项目状态”可切换进行中、已结束、已归档或全部。筛选保存在地址中，刷新或分享链接会保留。列表统计与当前状态范围一致。

维修流程：在“已结束”或“已归档”中找到项目，选择“重新激活”，再添加维修任务；处理完后再次结束。归档项目也可先“恢复为已结束”，继续保留在历史项目中。

结束或归档前，系统列出未完成的末级任务，要求确认保留其当前状态。已作废任务和有子任务的汇总行不重复计算。任务不会自动完成、删除或改期。重新激活也不会重置任务、阶段、进展或原有资料。

## 数据与权限

- 状态操作写入项目历史，保留操作者和变更前后内容。恢复状态统一使用状态管理入口；历史恢复不能绕过归档限制。
- 归档只读覆盖项目字段、进展、任务及子任务、排期、批量操作、合并和资料上传。服务端独立校验，旧页面或直接请求也不能继续编辑归档项目。
- 原附件可继续查阅和下载；数据导出保留归档项目及其任务。完整数据导入或工作区迁移仍按已有导入范围执行，并非日常编辑入口。
- 沿用现有工作区访问和写入权限，没有新增角色或自动删除策略。
- 旧数据未记录状态时视为“进行中”，无需批量改写历史数据。浏览器演示和共享后端都保存状态。
- 默认工作台、任务列表和任务风险提醒只计进行中项目；明确指定历史项目或项目集合时仍可查阅其任务。历史统计保留全部项目，不删除历史工作量。

## 接口

`POST /api/projects/:id/lifecycle` 接受当前 `version`、目标 `lifecycle`（`active`、`closed`、`archived`）及可选 `confirmOpenTasks`。沿用认证、防重复提交和事务保护；版本冲突或未确认未完成任务时返回 409。

`GET /api/projects` 默认返回进行中项目，可用 `lifecycle=closed`、`archived` 或 `all`。工作区快照仍保留所有状态，便于历史查阅和完整导出。
