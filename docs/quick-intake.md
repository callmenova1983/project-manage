# Quick intake

Open **Quick intake** from Projects or the workspace menu. Paste labeled English/Chinese text, paste a table, or choose/drop a TXT, CSV, TSV or XLSX file. Review candidates, adjust their target project and details, select the rows to create and confirm the final summary. Existing project fields are never silently overwritten: choosing an existing project adds a task only.

## Parsing and review

- Deterministic **rule-assisted** extraction; no model request or AI connection is implied. Keyboard/system dictation can enter text; the application does not record or upload audio.
- Chinese/English project, client, owner, stage, task, assignee, status and due-date labels/headers are recognized. Header mapping can be adjusted; multiple workbook sheets can be selected. Unsupported or missing information remains editable. Relative/invalid dates are flagged rather than invented.
- Files are parsed in the browser. XLSX parsing uses pinned `read-excel-file@9.3.12` in a dedicated worker. See the [maintainer's documentation](https://gitlab.com/catamphetamine/read-excel-file/-/raw/master/README.md). The reader does not execute formulas; it reads stored values. Legacy XLS and password-protected workbooks are not supported; export them to XLSX/CSV first.
- Limits: 2 MB file, 20 sheets, 200 data rows / 30 columns per sheet, 200,000 source characters, 20 MB declared archive expansion and a 15-second worker timeout. These limits are intended for reviewed batches rather than large database imports.
- Names/aliases are matched to existing projects. Ambiguous matches, unknown stages and uncertain dates are explicitly flagged. Duplicate project names or task titles need an additional confirmation. Date fields do not silently assign a work week.

## Save first, complete later

A recognizable project name or task title is enough. `client` can be an empty string; project `owner` and task `assignee` accept empty strings and display as unassigned (capture uses the explicit `Unassigned` sentinel). `dueDate` / `workWeek` remain nullable. Missing stage uses the reserved `unclassified` value, displayed as **Stage to complete / 阶段待补**, never inferred as Potential. The responsibility field remains Unassigned until supplied. Required structural API keys are generated by the draft normalizer; the user does not have to fill them.

Unresolved tasks use a clearly marked **Intake inbox** container. The `intakeInbox` flag excludes it from business-project totals and stage charts; its tasks remain included in real leaf-task statistics. This maintains the existing non-null task/project relationship without inventing a business project. Task editors can later assign standalone tasks to another project and add owner/date details. Parent/child tasks cannot be moved individually; version checks and workspace isolation still apply. Project editors allow name-only drafts and later completion.

New rows with the same normalized project name merge only missing fields, regardless of which row supplies them. Conflicting known clients, owners, stages or other details block the entire batch and name the conflicting field. Review and correct the rows (or explicitly exclude a row); the parser never chooses a winner or silently creates another same-name project.

Explicit repeated task labels and project labels on one line are split into separate candidates, while their original source line remains unchanged. Plain semicolon-separated items are supported. Exact unique names/aliases can select an existing project; partial or conflicting names only suggest candidates and default to the inbox. Missing fields do not require per-field/per-row confirmation. One final review covers the selected rows and warnings; actual duplicates still require the separate duplicate acknowledgment. Existing project fields are not overwritten by capture; later changes use the normal versioned editors.

The synthetic regression set includes missing fields, task-only tables, exact/partial/conflicting aliases, one-line multiple tasks across projects, relative/invalid/contradictory dates, original provenance, repeated save, later assignment/completion, stale edits and protected undo. `tomorrow`, `下周五` and timezone phrases are deliberately left unresolved. This deterministic parser does **not** establish general natural-language understanding, implicit pronoun resolution or reliable extraction from arbitrary vague prose. The Qwen integration tests intercept transport; **no live model quality, latency, region, billing or fuzzy-language acceptance test has been performed**. A real test remains pending explicit region/budget and a provisioned backend secret. No old conversation key was used.

## Unsubmitted draft recovery

Quick intake now keeps a temporary, unsubmitted draft in this tab using sessionStorage, separated by adapter mode, workspace and account. After a reload or route return, choose Restore draft or Discard draft. Only the selected worksheet is retained. Source, mapping and reviewed edits are preserved; confirmations reset and target project versions are rechecked on submission. Successful saves, Cancel and explicit sign-out clear the current draft. Automatic session expiry keeps it for the same account to recover after signing in. Drafts expire for recovery after 24 hours; storage errors show an explicit warning. Closing the tab or browser recovery policies may remove them earlier. This is not shared persistence or an offline queue. See [recovery evidence and limits](m1-recovery.md).

## Storage and rollback

`WorkspaceApi.applyIntake` applies a single reviewed batch. The server validates the entire batch and persists project/task changes, original row evidence, audit history and a batch receipt in one SQLite transaction. Existing project versions are checked against the version captured during review. HTTP retries use the existing idempotency mechanism. Invalid later rows leave no partial creations.

The browser demo implements the same contract in its isolated local snapshot, with one storage write. It never calls the server API. Completed batches can be re-opened after reload under Recent intakes.

Undo requires explicit confirmation. It removes only entities created by that batch and records the reversal. Any edited/missing creation or later task/subtask dependency blocks undo; it never overwrites newer work. Exact source cells or text and source row numbers remain in the audit record. Only the 30 most recent batches are listed; server receipts remain stored.

Migration `004_intake.sql` adds the receipt table and index; existing projects, users and credentials are untouched. This increment does not enable provider calls or deploy the application.
