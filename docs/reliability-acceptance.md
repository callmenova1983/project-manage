# 合成协作与容量验收

本页保留 `6952c81` 批次的历史测量（筛选 p95 617ms）。后续定位、同环境重新测量和两轮优化结果见 [筛选性能报告](filter-performance.md)；请勿将本页历史数据当作最新结果。

本批针对已有实现补充证据，不增加业务功能或部署。所有账号随机生成凭据，仅在 `/tmp/pm-reliability-*` 的私有临时 SQLite 中创建，最终清理；没有真实工作区数据、真实模型请求或新付费依赖。真实模型始终关闭。原有双会话冲突、恢复、幂等、草稿、语言/主题测试继续保留，新测试覆盖更长的交错执行与规模。

## 重复执行

```bash
npm ci
npm run build
npx playwright install chromium
node scripts/check-collaboration.mjs
node scripts/measure-scale.mjs
node scripts/profile-filter.mjs
npx playwright test tests/e2e/model-observability.spec.ts
```

本机依次运行这些 CPU 密集检查。脚本使用随机空闲 loopback 端口、编译后的 Web/API 和独立数据库；不需要运行 `setup:local`，不会读取或覆盖 `data/project-manage.sqlite`。CI 的独立 `reliability` job 运行两项编译产物检查并上传 `reliability-evidence`；常规 `verify` job 运行完整单元/API/E2E 和原有运行检查。

## 五会话、20 组交错执行

五个不同成员、五个独立 Cookie 容器，三个桌面视口和两个 390px 视口。每一组：

1. 五人同时编辑同一项目的同一版本，服务端处理后丢弃所有响应，核对实际只有一个 200 和四个 409。
2. 五个浏览器都进入离线，重试保存；每个输入草稿仍在编辑器中。
3. 恢复联网和正常同步，再次重试；三个尝试沿用同一请求标识。胜者得到原写入结果，另外四人看到最新版本与冲突，草稿保留至明确加载最新版本。
4. 五人分别并发提交两次同一任务创建请求，每人只得到一个任务。随后检查实际数据与审计数量，不能仅凭返回 200 判定没有重复。

20 组预期总量为 20 次项目更新、100 个新任务、120 条审计，项目版本均为 2。每组至少间隔八秒，以遵守未修改的 300 请求/分钟保护；登录、CSRF、版本和幂等规则均未减弱。注入的断网和明确冲突日志单独计数，其他浏览器错误均导致失败。`artifacts/collaboration.json` 保存逐组结果。

这是浏览器故障注入与本地真实 SQLite 的回归，不等价于物理网络故障、多进程 SQLite 竞争、真实五人在线或长时间压力验收。

## 200 项目、5000 任务测量

200 个合成项目，每个 25 个叶子任务，工作范围沿用合成种子的日历安排。基线使用 `c41795d` 编译产物；优化后使用本批产物。在同一本地 Node/Chromium 环境顺序运行，没有同时执行构建或其他测试，不做 CPU/网络节流。

- 首屏：20 个全新浏览器上下文，无 HTTP 缓存，复用已经认证的会话；从导航开始到 200 行存在并经过两帧。服务端和文件系统是温热的，不计人工登录。这是脚本观察到的页面可用时间，不是 FCP/LCP。
- 筛选：每次首屏后输入完整唯一名称，再清空，共 40 次；测输入事件至结果行数正确并经过两帧，不含 Playwright 输入动作时间。
- 同步：五个独立登录且可见的上下文，四次已确认的写入，等待原有 20 秒轮询显示更新，共 20 次观察；不使用在线事件或手动刷新。每组五个观察存在相关性，不能描述成 20 个独立网络实验。
- 快照：20 次 HTTP 请求并解析 JSON；记录载荷字节数。p95 使用 nearest-rank；保留全部样本和最大值。

本地目标为首屏 p95 3 秒、筛选 200 毫秒、同步 25 秒；它们是诊断目标，CI 记录实测值，不将不同托管硬件的性能目标当成功能断言。

2026-10-13 本地结果：Node 24.19.0、Chromium 154.0.8037.57、Linux 6.18.44、Xeon Platinum 8573C、环境可见 5 个逻辑 CPU/17.59 GiB 内存、1536×1024、浏览器默认浅色、无节流。API 快照为 1,641,075 字节。这是共享执行环境的观测值，不是独占硬件或生产 SLA。

| p95 指标 | 基线 | 优化后 | 目标 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 首屏 | 4269.2 ms | 1918.1 ms | 3000 ms | 达到本地目标 |
| 筛选（缩小/恢复合并） | 3606.6 ms | 617.0 ms | 200 ms | **未达到** |

筛选拆开看，优化后缩小到一行 p95 449.2 ms，恢复 200 行 p95 705.1 ms。没有排除这些慢样本来宣布达标。独立的五次 Chromium CDP 诊断中，恢复筛选耗时 429–494 ms，主线程 TaskDuration 417–495 ms，LayoutDuration 约 41–49 ms，RecalcStyleDuration 约 28–30 ms；这些时间包含关系不同，不能相加，也不能把未归类差值直接当成某个 JavaScript 函数耗时。现有 200 行重建/布局仍有成本；如必须达到 200 ms，需要另行评估减少同时渲染的行或组件更新范围，本批未扩大架构。

原始样本：[基线](evidence/scale-baseline.json)、[优化后](evidence/scale-final.json)、[CDP 诊断](evidence/filter-profile.json)、[20 组协作](evidence/collaboration.json)。优化仅移出逐任务重复的日期计算，并按项目缓存任务分组和范围汇总；叶子任务、工作日与截止日口径保持不变。尚未测试真实移动 CPU、慢网、海量历史、所有任务列表一次展示 5000 项或多实例部署。

## 模型统计

回归先复现了一个实际缺口：包含有效用量的截断输出因 `finish_reason` 校验先失败，原来把 token 记成未知。现在先验证并保存独立用量，再继续严格拒绝无效建议。回归要求 140/2048 token、`AI_INVALID_OUTPUT`、一次尝试和未知费用同时保留，失败重放不增加调用或额度。

其他新增 API 测试验证失败调用计入额度、耗尽/过期阻止发送、拒绝发送不伪造供应商日志；已有测试覆盖缺配置、权限和未知用量。八种 EN/中文 × 深/浅色 × 桌面/390px 组合检查管理页缺配置、失败/进行中日志、额度耗尽/过期、费用未知、键盘横向滚动与 axe。管理页渲染测试明确使用合成 HTTP 响应；供应商请求测试使用注入 mock，没有网络调用或真实 AI 连通结论。

## 仍需实际环境的步骤

- 用户指定的托管环境需另行部署并配置真实 HTTPS 来源、证书、私有持久卷、备份恢复和监控。本批没有部署或合并。
- 用户实际 iOS/Safari、软件键盘、后台/前台与断网恢复需真机验收；Chromium 390px 不能替代它们。
- 真实模型需用户选择区域并安全提供服务端凭据、明确额度和允许外发的测试内容，另行授权测试。本批未配置凭据或进行付费调用。
- 应用内录音与语音转写仍未实现；没有将系统听写输入框包装成已接入转写服务。
- 原 Library 视觉参考获取和现有代理 CONNECT 403 的边界不变；没有绕过网络限制，也不宣称原图像素验收。
